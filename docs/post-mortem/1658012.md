# AB#1658012

## Executive Summary

Every Auro component publishes a machine-readable "manifest" that describes it: what it is called, what options it has, and what each option does. Documentation sites, design tools, and AI assistants all read this file. The manifest for `auro-card` already followed the design system's rules, but nothing checked that it stayed that way, so a future change could quietly break it and ship without anyone noticing.

This work adds an automatic quality check to the `auro-card` build. If the manifest breaks the design system's rules, the build now fails instead of publishing a bad file. It also rewrites the component's descriptions, documentation pages, and examples to follow the design system's content guidelines and to match what the component actually does, so the manifest and the documentation generated from it are accurate and readable by non-engineers.

Ticket: [AB#1658012](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1658012) ("Build Correct CEM - auro-card")

## The Problem

The `custom-elements.json` manifest for `auro-card` passed the design system's strict check with zero findings before this work, but nothing enforced it. A change that broke the manifest would only be discovered later, by a consumer.

Separately, parts of the documentation were wrong, unclear, or broken. The `href` description said it "disables the default CTA slot", but the component always renders that slot. The `relative` description promised a URL re-write feature that the hyperlink used by the card does not act on. The Navigation docs said a card link could point to "anything else a URL can address", but script-style links are removed. One example (`advanced.html`) put its content in a slot the card doesn't have, so that content never appeared. Headings and example text were inconsistent in capitalization and wording.

## Root Cause

- `package.json` had `"build": "auro build"` only. `auro build` generates `custom-elements.json` but never validates it against the contract, so no build step could fail on a bad manifest. The repo was also on `@aurodesignsystem/auro-cli` `^3.7.1`, which predates the `cem-check` command.
- `src/auro-card.js`: the class description was a single sentence with no summary or example, slot and part descriptions were terse ("Apply styles to the named cta slot container"), and `variant`, `role`, `href` and `relative` did not describe what they actually do. No `@cssprop` tags documented the colors the card owns.
- `docs/partials/*.md` and `apiExamples/*.html` had not been reviewed against the content guidelines or the code: the Navigation claim about URLs (auro-hyperlink's `safeUrl` drops `javascript:`, `data:`, and `vbscript:` URLs and upgrades other URLs to `https:`), Title Case card text, `<h3>` headings where the docs recommend `<auro-header>`, and `<div slot="">` in `advanced.html`.
- `src/styles/tokens.scss` defined `--ds-auro-card-texticon-color`, which no style used and no documentation mentioned.
- `variant` was declared as a reactive property, but no JS reads it. Only the styles use it, through `:host([variant=…])` attribute selectors.

## The Fix

- `package.json`: added `"cem:check": "auro cem-check --strict"` and changed `build` to `"auro build && npm run cem:check"`, so a non-zero exit from the check fails the build. Upgraded `@aurodesignsystem/auro-cli` from `^3.7.1` to `^5.1.0` (the ticket asked for 4.0.0 or later).
- `auro-cli` 4.0.0 requires `ADO_TOKEN` to be forwarded by the release-candidate workflow. `.github/workflows/release-candidate.yml` already forwards it (commit `052fa6d`, on the base branch before this work), so no workflow change was needed here.
- `src/auro-card.js`: rewrote the class JSDoc (audience-friendly intro, key capabilities, example, `@summary`), rewrote slot, `@csspart`, and property descriptions to the Auro [content guidelines](https://github.com/orgs/AlaskaAirlines/discussions/660), added `@category` and `@relevantWhen` tags, added `@cssprop` entries for `--ds-auro-card-border-color` and `--ds-auro-card-background-color`, wrapped `auro-hyperlink` link text in code font, and documented how `variant`, `href`, and `role` interact.
- `variant` is now an attribute only. It is removed from `static get properties` and documented with an `@attr` tag in the class JSDoc, so it still appears in the manifest.
- `docs/partials/`: rewrote the description and use cases, corrected the Navigation URL claim, fixed a spaced dash and passive wording, changed "will create" to "creates", and aligned the index headings to the shared template ("Use cases", "Examples").
- `apiExamples/`: sentence-case card text, `<auro-header display="500">` for headings, and `advanced.html` now uses the `header` and `description` slots with `href` on the card.
- `src/styles/tokens.scss`: removed the unused `--ds-auro-card-texticon-color`.
- `docs/api.md`, `custom-elements.json`, and `README.md` were regenerated by the build.

## Why This Works

- `auro cem-check --strict` treats any finding as a failure, and `&&` in the `build` script propagates that exit code, so CI and local builds both stop on a bad manifest.
- The check validates the manifest after `auro build` has generated it, so it always inspects the file that will actually be published.
- Descriptions were checked against the component's code and styles (`render()`, `setRole()`, `src/styles/style.scss`, `color.scss`) and against the installed `auro-hyperlink` build, rather than the previous wording.
- Making `variant` an attribute-only item changes no behavior, because the styles only match the attribute. The `@attr` tag keeps it in the manifest and the API table.

## Outcome

- The `auro-card` build now fails if its manifest breaks the design system's rules. `npm run build` passes and the strict check reports "CEM contract clean — no violations", including after the documentation rewrite and the `variant` change.
- The component's description, option list, slot and style-part notes, doc pages, and examples are accurate and written in plain language.
- All 7 existing tests pass, and the published package contents include `custom-elements.json`.

## Learnings

- Strict CEM checking costs almost nothing to add when the manifest is already clean, and it turns a silent regression into a build failure. Add it to every component's `build` script.
- Components on older `auro-cli` majors do not have `cem-check`. Upgrade the CLI first, and check that the release-candidate workflow forwards `ADO_TOKEN` (required from 4.0.0).
- Write JSDoc to the Auro [content guidelines](https://github.com/orgs/AlaskaAirlines/discussions/660) from the start. Descriptions that only repeat the attribute name are the most common miss; say what the option does and give a typical value.
- Check descriptions against the code, and against dependencies when a claim depends on them. The old `href` description claimed the CTA slot was disabled, and the Navigation docs claimed any URL works, but `auro-hyperlink` removes script URLs.
- Check API examples as well as prose. `advanced.html` used an empty slot name, so its content never rendered, and it isn't referenced by any doc page. Consider deleting it.
- A property that only styles read can be an attribute with an `@attr` tag. This keeps it in the manifest without a reactive property. The trade-off is that setting `el.variant` in JavaScript no longer updates the attribute; use `setAttribute("variant", …)`.
- `auro-card` forwards a `relative` attribute to `auro-hyperlink`, but the hyperlink build in use does not read it. The description says so. Whether to keep or remove the attribute is a separate decision.
- The branch points the `@aurodesignsystem/auro-hyperlink` dev dependency at an unreleased build (`npm:@aurodesignsystem-dev/auro-hyperlink@^0.0.0-pr369.0`) and `src/hyperlinkVersion.js` at `0.0.0-pr369.0`. That swap is not part of this ticket and must be restored to a published version (for example `^8.0.3`) before the change merges or ships.
- Commit `9c7ff32` also removed about 430 lines of bundled `node_modules/npm/...` entries from `package-lock.json`. The docs work did not cause that change, so check it before merging.
- Pre-existing lint errors (`biome` format on `src/auro-card.js` and `src/hyperlinkVersion.js`, `useNumberNamespace` in `test/auro-card.test.js`) are unrelated to this change and were left alone.
